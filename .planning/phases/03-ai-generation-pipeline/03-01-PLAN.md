<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> BFF API | Untrusted user input crosses from the mini program into upload confirmation and job creation endpoints. |
| BFF API -> OSS | Confirmed asset keys and signed URLs cross into object storage operations. |
| BFF API -> PostgreSQL | Job creation and event writes must preserve idempotency and tenant scoping. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | T | generation_assets confirm endpoint | mitigate | Validate that confirmed OSS keys were issued for the current tenant, reject foreign keys, and persist the asset only after existence is verified in OSS. |
| T-03-02 | D | generation_jobs create endpoint | mitigate | Enforce a DB unique constraint on `client_request_id` and return the existing row on `IntegrityError` so replayed requests cannot create duplicates. |
| T-03-03 | I | generation_jobs poll endpoint | mitigate | Return tenant-scoped jobs only, keep mutable rule rows out of responses, and generate short-lived signed URLs on demand instead of exposing bucket objects directly. |
</threat_model>
