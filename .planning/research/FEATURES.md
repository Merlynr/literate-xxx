# Feature Landscape

**Domain:** AIGC 电商商品宣传图生成平台（微信小程序）
**Researched:** 2026-05-12
**Overall confidence:** HIGH

## Executive Summary

XX甄选是一个以 AI 生成商品宣传图为核心价值的微信小程序电商平台。用户只需上传一张实物照片，选择风格模板，系统自动通过 Vision API 分析 Demo 图生成描述性标签，再调用 Image Gen API 生成可直接上架的成品级宣传图。当前产品线聚焦光伏板下种植的优质农产品。

该领域已有多个竞品和参考平台（如美间AI、即梦AI、Pic Copilot、ZMO.ai、Flair.ai 等），但大多数是 Web 端 SaaS 工具，微信小程序 + 电商闭环 + 运营可配置词条/规则引擎的组合是差异化方向。

功能设计严格遵循规格文档 v2.0（2026-05-11），结合竞品分析进行补充和校准。

## Table Stakes（必须有，缺了用户会走）

这些是用户进入产品后立即期望的基本功能，缺失任何一项都会导致产品不可用。

| 功能 | 为什么是必须的 | 复杂度 | 依赖 | 备注 |
|------|--------------|--------|------|------|
| **微信登录与用户绑定** | 无登录无法使用任何功能 | Low | 微信 OAuth | 首登绑定租户（tenant_id） |
| **商品类目选择** | 驱动下游词条/规则/模板解析 | Low | 后台类目 CRUD | 电商风格类目导航（如红皮土豆/黑珍珠土豆） |
| **风格模板选择** | 用户需要知道"生成什么样的图" | Med | 后台风格 CRUD + 封面图 | 宫格卡片 + 选中态；每个风格关联规则版本 |
| **实物照片上传（相册/拍照）** | 核心输入——没图就没法生成 | Low | OSS 预签名上传 | 格式/大小限制；客户端+服务端双重校验 |
| **Demo/参考图上传** | 提供风格参考，是 AI 流程的关键输入 | Low | OSS 预签名 | 同上 |
| **AI 生成全流程（Vision + Image Gen）** | 整个产品的核心价值 | **High** | Vision API + Image Gen API + Celery 异步队列 | Vision 分析 Demo → 生成标签 → Image Gen 出图 |
| **任务状态与进度展示** | AI 生成需要 10s+，用户需要知道"正在发生什么" | Med | 任务状态机 (queued→running→succeeded/failed) | 轮询退避；预计时长文案 |
| **生成结果预览与下载** | 交付产出物——宣传图成品 | Low | OSS 签名 URL | 水印图 + 高清原图；保存到相册 |
| **任务列表（我的作品）** | 历史访问，不需重复生成 | Low | 任务查询 API | 左图右文列表；下拉刷新 |
| **额度/配额显示** | 用户需要知道还能生成多少张 | Low | 额度摘要 API | 首页 + 我的页面展示 |
| **隐私协议与用户条款** | 法律合规要求，首次生成前必须勾选 | Low | — | 勾选区；阻断未同意用户 |
| **任务幂等性（防重复提交）** | 防止用户重试导致重复扣费 | Med | client_request_id 唯一约束 | 同一 ID 重试返回同一 job_id |

### Admin/后台 运营必须功能

| 功能 | 为什么是必须的 | 复杂度 | 依赖 | 备注 |
|------|--------------|--------|------|------|
| **类目/风格 CRUD** | 运营需要配置商品类目和风格模板 | Med | PostgreSQL + 后台 UI | 表格+抽屉模式 |
| **词条库 CRUD** | AI 提示词的运营可控部分 | Med | ai_term + ai_term_scope 表 | 类型/权重/排序/审计 |
| **宣传规则管理** | 定义词条选取、槽位组装、画幅/水印策略 | **High** | promo_rule + promo_rule_version 表 | 可版本化；新版本仅作用于新任务 |
| **定价/套餐管理** | 额度包的创建与管理 | Med | pricing_plan 表 | 张数/有效期/适用类目 |
| **生成任务查询与监控** | 排查失败原因，追踪 AI 调用 | Med | 任务查询 + LEX trace | 筛选、状态、失败原因详情 |
| **配额扣减与流水** | 计费基础——冻结/扣减策略 | **High** | quota_account + quota_ledger 表 | 方案 A（冻结）或方案 B（成功扣）二选一 |

## Differentiators（竞争优势，让用户选择 XX甄选 而非竞品）

| 功能 | 价值主张 | 复杂度 | 竞品状态 | 备注 |
|------|---------|--------|---------|------|
| **Vision API 自动学习 Demo 图风格** | 独特创新：AI 自动分析参考海报，生成描述性标签（背景、光影、构图、风格），无需手工写 prompt | **High** | 竞品多用固定模板/preset，不支持 Demo 图学习 | GPT-4o-mini 可切换多模型 |
| **运营可配置词条库 + 优先级系统** | 运营维护正向/负向/前缀/品牌约束等词条片段，按类目×风格×标签组合；无需改代码即可调优 | **High** | 竞品多为硬编码 prompt 或简单模板替换 | 支持冲突检测与兜底策略 |
| **规则引擎 + Prompt 槽位组装** | 宣传规则定义词条选取、槽位顺序、默认负面词等，版本化管理 | Med | 竞品多为黑盒 prompt | 规则版本快照——历史任务不受后续改规则影响 |
| **任务创建前试算（预计消耗）** | 提前告知用户"本次生成消耗 N 张额度"，降低摩擦和意外扣费感 | Med | 竞品多按次收费，无试算 | 确认页显示"预计消耗" |
| **水印自动贴合** | 品牌一致性——所有输出图自动加水印，无需用户操作 | Low | 部分竞品有，但多数需付费 | 同时存储水印图和原图 |
| **多 AI 引擎支持** | Vision API 默认 GPT-4o-mini，Image Gen 可切换 Codex/Gemini | Med | 竞品多绑定单一模型 | 抽象适配层，便于后续切换 |
| **多租户数据隔离** | tenant_id 全局隔离，支持 B2B 扩展 | Med | 竞品多为单租户 SaaS | v1 轻量，但架构预留扩展性 |
| **微信小程序原生体验** | 无需下载 APP 或访问网页，微信内直接使用 | Low | 竞品多为 Web 端 | 低门槛获客 |

## Anti-Features（v1 明确不做的事情）

| 反特性 | 为什么不做 | 延迟到 | 替代方案 |
|--------|-----------|--------|---------|
| **图片预处理/抠图（rembg 等）** | 增加复杂度、延迟和 ML 推理依赖。AI 可以直接处理原图。 | P1+ | 直接将实物图喂给 Vision API。如生成质量不足再回退。 |
| **LEX-AI 直连** | 规格文档明确用 Codex/Gemini API，LEX 增加供应商锁定风险。 | 暂不考虑 | 用 Codex API 做 Image Gen。架构已支持引擎切换。 |
| **微信支付** | 审核流程重，增加大量接入工作量。计费前端只做 UI 预留。 | P1 | 前端显示额度/套餐为 UI 壳子，后端无支付流。 |
| **电商平台 API 对接** | 淘宝/京东/拼多多 API 复杂、限频、经常变更。无客户需求。 | P2 | nullable 字段预留 external_product_mapping。 |
| **ERP 集成** | 无现有 ERP 客户。过早抽象。 | P2 | Job 表预留 biz_doc_type + biz_doc_no nullable 字段。 |
| **人工审核队列** | 减慢核心流程。用户要即时结果。 | P1 | AI 输出直接返回用户。合规需要时再加。 |
| **分销拼团等复杂营销** | 完全不同的领域。会膨胀范围。 | 非目标 | 聚焦图片生成质量，不做营销机制。 |
| **OpenAPI / 开发者门户** | 没有外部开发者。过早。 | P2 | 有真实集成需求时再建。 |
| **API Key 管理 UI** | 目前仅内部使用。 | P2 | 后端存哈希密钥，UI 延后。 |
| **规则模拟/预览** | 运营侧 nice-to-have，非用户面向。 | P2 | 运营可通过实际生成测试。 |
| **RBAC 角色权限** | 单运营者模式够用。 | P1 | 所有后台用户完全权限。团队扩大后加。 |
| **限流（Rate Limiting）** | 单租户、低量启动。QPS 不会是瓶颈。 | P1 | 并发用户上来后再加。 |
| **批量生成** | MVP 聚焦单张生成闭环。 | P1+ | 先做好单张的完整体验。 |
| **生成历史对比/AB 测试** | 功能精细，非核心需求。 | P2+ | 用户可手动对比不同生成结果。 |
| **图片编辑/后处理** | 增加前端复杂度。核心价值是"一键出图"。 | P1+ | 如需调整可重新生成。 |
| **多语言支持** | 当前仅中文市场。 | P2+ | 如有国际化需求再加。 |

## Feature Dependencies（功能依赖关系）

```
用户登录 → 选择类目 → 选择风格 → 上传实物图 + 参考图 → 组合校验 → 试算 → 创建任务（幂等）
    ↓              ↓           ↓              ↓                        ↓          ↓
 额度检查     词条解析    规则版本快照    OSS 存储              配额校验/冻结   任务队列
    ↓                                                                         ↓
 套餐购买                                                              AI 调用 (Vision + Image Gen)
                                                                              ↓
                                                                     任务状态轮询 → 结果展示
                                                                              ↓
                                                                    水印图 + 高清图 → 下载/存相册
                                                                    成功 → 确认扣减
                                                                    失败 → 释放冻结

后台依赖链：
类目CRUD ←→ 风格CRUD ←→ 词条CRUD ←→ 规则管理 ←→ 规则版本发布
套餐管理 ←→ 配额扣减 ←→ 流水记录
任务监控 ←→ 失败诊断
```

### 关键路径

**端到端主流程**：登录 → 类目/风格 → 上传 → AI 生成 → 状态 → 结果 → 下载
**后台并行路径**：类目/风格/词条 CRUD + 定价 + 配额 必须在用户测试前就绪

## MVP Recommendation（MVP 推荐）

### 必须上线（Phase 1 — 核心闭环）

1. **微信登录**（T1）— 入口门
2. **类目 + 风格选择**（T2, T3）— 引导流程
3. **实物图 + 参考图上传**（T4, T5）— 核心输入
4. **AI 生成全流程**（T6）— 核心价值（含 Vision 分析 + Image Gen 出图）
5. **任务状态 + 结果展示**（T7, T8）— 完成闭环
6. **后台基础 CRUD**（A1, A2）— 运营能用

### 第二批（Phase 2 — 可用性提升）

7. **任务列表 + 历史**（T9）
8. **额度/配额系统**（T10, A5, A6）— 计费基础
9. **宣传规则引擎 + 版本管理**（A3）— 质量控制
10. **试算功能**（D5）— 降低摩擦
11. **水印自动贴合**（D6）— 品牌一致性
12. **任务幂等**（D8）— 防重复扣费

### 第三批（Phase 3 — 运营增强）

13. **词条优先级 + 范围配置**（D4）
14. **后台任务监控增强**（A4）
15. **隐私协议 + 用户条款**（合规）
16. **多 AI 引擎切换**（D7）

### 明确推迟

- 图片预处理/抠图 → P1+
- 微信支付 → P1
- 电商平台对接 → P2
- 人工审核 → P1
- 复杂营销 → 非目标
- 批量生成 → P1+
- 图片编辑/后处理 → P1+

## Complexity Estimate Summary

| 复杂度 | 功能 | 占比 |
|--------|------|------|
| **Low**（1-2天/个） | 登录、类目选择、实物图上传、参考图上传、结果预览下载、任务列表、额度显示、隐私协议、水印、小程序体验 | ~50% |
| **Medium**（3-5天/个） | 风格选择、任务状态展示、幂等性、类目/风格 CRUD、词条 CRUD、定价管理、任务监控、试算、多引擎、多租户 | ~30% |
| **High**（5-10天/个） | AI 生成全流程、宣传规则管理、配额扣减流水、Vision 自动标签、词条优先级系统、规则引擎 | ~20% |

3 个高复杂度功能（AI 管线、规则引擎、配额系统）占总功能数的 ~20%，但约占总开发工作量的 ~60%。
